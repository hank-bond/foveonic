# Small previews

The processing engine must support sensor-layer reduction at any positive power-of-two divisor of native width and height. Full, Fast and Draft select divisors one, two and four. Thumb selects divisor eight on Merrill and Quattro. On Classic, Thumb uses divisor four, the same working resolution as Draft, because these cameras start at lower native resolution. This choice applies to the complete processing pipeline and idle preparation, not only auxiliary analysis. Explicit numerical scale requests retain their requested divisor. These names describe dimension ratios, not fixed megapixel counts. A 16 MP photograph yields approximately 1 MP in Draft and 0.25 MP in Thumb. Keep the release defaults unchanged until image quality and speed have been reviewed.

Working sensor reduction must use non-overlapping area means. At divisor d, each output cell averages only its covered d×d native block. Each native sample contributes to exactly one logical cell. Final partial blocks average their actual samples. Processing padding repeats completed cells and must not mix neighboring cells. Signed-code consumers round once after the complete two-dimensional mean. Native Full image processing and internal camera reconstruction resamplers remain unchanged. Adaptive Tone’s analysis branch uses the same area means as working previews, even when the requested photograph is Full. Its fitted Full result may therefore change slightly with this sampler migration. Independent-noise standard deviation follows 1/d for complete blocks. Display interpolation is separate from these numerical buffers. UI preview speed and sufficient culling detail take priority over export-level resampling fidelity.

Reduction must filter calibrated sensor layers before expensive reconstruction. Preserve original source samples and native sensor-coordinate corrections. Do not expose a resize of an already reconstructed photograph as sensor-level reconstruction support. Existing Fast and Full processing must remain available.

The native prefix must be limited to basic calibration and corrections whose evidence depends on original sensor locations. Calling an operation a sensor correction does not establish that its complete image processing must precede pooling. Neighborhood filtering, row estimation, highlight processing and reconstruction should consume explicit working geometry after the earliest valid reduction boundary. Downstream operations consume working-resolution buffers. Any additional input must use that same working grid. Preserve separate clipping or defect evidence only where the selected algorithm demonstrably requires it. Otherwise detection and correction operate on the reduced samples. Keep the authoritative Full operation order and numerical behavior unchanged.

Merrill highlight recovery runs after sensor pooling in Color and Monochrome previews. The selected approach retains ordinary numerical area means and carries original per-channel clipping evidence onto the same working grid. Standard recovery and both Color Field methods must use that evidence rather than rediscover clipping solely from the averaged value. Averaging below a clipping threshold must not erase known damage. Camera saturation evidence may identify clipping below the digital code ceiling. Preserve native Full recovery and its original saturation-map behavior. Black-level measurements and sensor-coordinate defect repairs remain before pooling. Map recovery support, valid bounds and repair sites beside the operation. Color Field solver cells retain enough working samples for donor classification. Separate healthy/clipped RGB maps and weighted recombination remain experiments and are not selected for application processing. Preview acceptance focuses on visible artifacts rather than tiny mean-brightness changes.

The scale divisor is a validated power-of-two value constructed at the processing boundary. Nodes trust that value without repeating its validation. Original camera metadata remains unchanged. Each node prepares only its required scale-aware parameters beside its implementation. Share coordinate, support and noise conversions where their meanings agree. Expensive repeated derivations may be reused through existing preparation ownership. Fractional final display or export resizing is separate from sensor-layer sampling.

Merrill Multiscale neighborhood filtering must follow sensor pooling for reduced photographs, in both Color and Monochrome. Preserve native Full and DNG order and arithmetic. The filter must account for calibration units, pooled noise variance, physical filter supports and original clipping evidence on the requested grid. A local calibration basis may approximate spatial gain within each pooled cell for previews. Its correction must return in calibrated units without recalibrating the photograph. Native shield measurement and guarded row estimation remain separate operations. Do not bypass selected filtering or retain a native image dependency solely for reduced filtering.

Merrill guarded-row estimation must also run on resized layers for reduced photographs. Its original and post-shield measurement images must use that same grid, independently of later camera repairs. Apply its result to the calibrated numerical image before Multiscale and highlight recovery. Scale the Gaussian supports, independent-noise model and row-offset prior beside the node. The prior describes high-pass row offsets and must account for row averaging and the projected filter response, rather than treating coherent rows as independent pixels. Preserve native Full, regional and technical DNG order and equations. A shared parameterized estimator may introduce floating-point rounding differences in native output. Bound those differences with numerical comparisons rather than maintaining separate shader configurations solely for bit identity. Reuse original clipping evidence and the shared local calibration basis.

Recorded framing, camera orientation, saved composition and native viewport coordinates must remain consistent. Sensor and processing alignment constraints must use edge-covered working-grid padding. Edits retain their requested values. Spatial controls must use the appropriate working-grid scale, while noise approximations require validation at each size.

Smart detail promotion, inspection and exports must use Full. Explicit Draft/Thumb remain workspace preview choices. Preview quality must not become an image sidecar edit. Validate completed reconstruction-changing edits separately from cached exposure edits. Compare appearance on original photographs before enabling a default.

Each camera family should use its existing processing recipe with scale-aware stages. Do not introduce a separate recipe that disables corrections solely to meet a Thumb timing target. First Thumb preparation from an already-decoded resident source targets about 120 ms. Disk-cache reading and decoding must be measured separately. A retained Thumb edit near 50 ms and eight-photo edit completion near 400 ms are investigation goals, to be measured on distinct retained sessions rather than inferred from single-photo repetition.

Every supported camera architecture and native RAW mode must run its complete selected processing recipe on the working grid. Monochrome, Classic range reconstruction, reduced RAW modes and Tiger must share this scale contract. A control or named output must not trigger a whole-recipe quality fallback or disqualify cached reuse. Native-coordinate sensor corrections precede pooling. Downstream operations receive explicit working geometry and physical sampling scale. Algorithmic alignment uses edge-covered padding instead of switching quality. Invalid source data remains an error.

Auxiliary analysis declares its sampling through the same geometry contract. Its grid must not be larger than the requested working grid. Recipes choose each consumer's analysis scale independently of the numerical operation. Shared preparation should own smaller-input geometry and framing so multiple consumers can reuse it. Processing-stage identity and effective settings must still distinguish incompatible inputs. Camera-authored native analysis conventions remain explicit. Retained roots come from reachable graph dependencies, not option whitelists, manually enumerated feature variants or duplicated control lists. A changed upstream dependency may require native input to rebuild that cut. Unchanged branches must remain reusable across edits and power-of-two scale switches.

Entering, leaving or committing Crop/Rotate must reuse compatible photographic pixels and preserve their actual working resolution. These presentation-only changes must not force Full or cancel matching in-flight pixel work. Explicit quality changes and photographic edits remain numerical processing requests.

## Reduced working-set ownership

A warm reduced-photo set should retain corrected reduced sensor inputs and useful small editing checkpoints. One bounded active owner must retain its restart inputs throughout edits. A separately bounded historical set may evict inactive photographs. Report active, historical and shared preparation storage separately. Native decoded CPU samples and full-resolution GPU checkpoints should be releasable for inactive photographs. Full detail and exports must recover authoritative native input on demand. Preserve the active Smart refinement path's reusable native work.

Reduced checkpoint validity must include source identity, working grid and all effective upstream correction choices. Native calibration, WB-dependent correction, highlight recovery, repairs and noise choices are not assumed to be fixed. Downstream edits should reuse a valid checkpoint. An upstream change must regenerate affected preparation rather than return stale pixels. Reduced buffers must keep explicit native-to-working geometry instead of being passed off as original sensor samples.

Shared preparation and post-reconstruction editing should remain usable by future camera families. This work does not require a new decoder family or a general camera plugin framework. The initial optimization is recorded in [its completed report](../../plans/archived/scaled-editing-optimization.md). Full option and scale support is tracked in [the structural implementation plan](../../plans/full-option-scaled-pipeline.md).
