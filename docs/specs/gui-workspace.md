# GUI workspace

## Requirements

- The desktop app **must** use the owner's layered-X artwork as its application icon. The light appearance **must** use a light neutral background with a lighter top and darker bottom and a softly lit graphite X. The dark appearance **must** use a softly lit light X on a dark background with the same colored slabs and geometry. Both **must** distinguish the colored slabs at small sizes and use a restrained opaque bevel that follows the light direction. Foreground Liquid Glass, refraction, and translucent glossy rims **must not** be applied. Preserve both the original and current logo as editable SVGs for future projection changes. Foreground scale is a visual-review choice; 90% of the background width is the current trial, not an Apple rule. Imported icon copies **may** adjust framing while preserving the original artwork. Dock icons **must** use Apple's production-compiled macOS margins and size renditions, not a full-canvas Composer preview or a guessed shrink percentage.
- On macOS 26, the supported local GUI workflow **must** build and launch a local `.app` bundle containing both appearances in one compiled Icon Composer asset. macOS **must** control icon appearance selection according to the user's system icon settings, without a static runtime Dock override. Building **must not** install or publish the app. The application and preference identities **must** remain stable. Direct Cargo launches are not the macOS icon workflow.
- The workspace **must** keep an organizer on the left, the selected image in the middle, and tools on the right. The organizer **must** offer icon and compact-list modes; resizing its pane **must** reflow the icon columns.
- Clicking an organizer image **must** give the icon grid or list stable keyboard focus. Left/Right **must** select the previous/next image; Up/Down **must** move by the current grid row or one list item. Navigation **must** stop at the edges, keep the selected image visible, and use the normal automatic-render selection path. Focus **must** remain in the organizer across selection changes and repaints until the user clicks elsewhere or moves focus with Tab. Organizer arrows **must not** interfere with focused editing fields.
- Navigator, Scopes, Editing, and Metadata sections **must** be collapsible and reorderable within the right pane. Floating sections and docking in other panes are deferred.
- The navigator **must** show the visible image region and support dragging to pan the main viewport. Below its image, it **must** display the current zoom percentage and offer 100%, 200%, and 400% buttons. Percentages **must** use physical display pixels per image pixel: 100% means one display pixel per image pixel, including on high-density displays. Preset buttons **must** preserve the image point at the viewport centre. Scrolling the tools pane **must** clip the navigator without compressing its image or changing alignment with the visible-region overlay.
- Double-clicking either the main viewport or the navigator image **must** switch from automatic Fit to the selected snap zoom, or from any fixed zoom to centered automatic Fit. Main-viewport zoom-in **must** preserve the image point under the mouse cursor, like scroll zoom. Navigator zoom-in **must** centre the clicked image location in the main viewport, constrained at image edges to avoid blank space. A single navigator click while fitted **must not** leave Fit.
- Clicking a zoom preset **must** zoom immediately without changing the snap target. Command-click on macOS (Ctrl-click elsewhere) **must** select that preset as the snap target without changing the current view. A colored underline **must** identify the snap target independently of the current zoom readout. The target **must** be an application preference, defaulting to 200% and persisting across image changes and application restarts. Navigator section and button hover popovers **must** explain selection, the underline, persistence, and double-click behavior.
- Fit **must** automatically scale and centre the whole image as the window or panes resize. After zooming, panning, or selecting a zoom preset, resizing **must** preserve image magnification and the visible crop's continuous top-left image coordinate, revealing or hiding pixels at the right and bottom. An axis that fits wholly within the viewport **must** remain centred. Moving the window without resizing **must not** change magnification or crop. Explicit Fit **must** restore automatic fit.
- One persistent Scopes section **must** switch between RGB histogram, RGB parade, and combined waveform. Scopes **must** analyze the currently inspected buffer. Histogram endpoints **must** follow the buffer's meaning in [pipeline inspection](./pipeline-inspection.md).
- A **Viewport only** toggle inside Scopes **must** select the visible image region shared with the navigator. Off selects the whole image and **must** be the default. The toggle **must** persist as a UI preference. Viewport scopes **must** follow pan, zoom, resize, and buffer changes without rerunning image processing. Larger regions **may** be downsampled.
- During viewport updates or input-toggle changes, the previous scopes for the displayed buffer **must** stay visible until matching results arrive. Updates **must not** insert blank frames.
- Scopes are visual editing guides. Waveform/parade samples **must** spread their weight across neighboring cells to give smooth traces, without changing histogram counts. Drawing **must** align to physical pixels and filter resizing without changing the density weights or brightness mapping.
- Buttons, checkboxes, and organizer selections **must** have rounded borders that brighten on hover and darker pressed fills. Buttons and organizer selections **must** be neutral when off/unselected and blue when on/selected, with subtle blue fills and borders. Hover and press **must** keep that state color. Checkboxes **must** stay neutral and show on/off with checkmarks. State symbols **must** remain visible, including when disabled controls are muted.
- Buttons and dropdowns **must** have at least 0.25em padding above and below text and 0.5em on each side. One em is the control's font size. Dropdown options and disclosure rows **must** use the same font-relative padding. Spacing between controls **must** stay unchanged.
- Dropdown options **must** fill their cells with square, borderless backgrounds and light gray text. Selected cells **must** be blue; unselected cells **must** be dark gray. Hovered text **must** be whitish, retaining blue for selected cells and using mid gray for unselected cells.
- White balance and Color mode **must** retain their labeled dropdown rows before the first rendered image and while selection metadata loads. Known saved values **must** remain visible; unresolved values **may** show a placeholder. Dropdowns **must** stay disabled until their camera choices are available. Loading those choices **must not** shift the editing controls below them or change photographic settings.
- Adjustment rows **must** use label, slider, then editable value order. Double-clicking a slider **must** reset its existing processing default. A focused value box **must** support Up/Down nudging, using 0.1 for floats and 1 for integers unless the parameter specifies another unit. Nudges **must** respect bounds, retain text editing/focus, and request a rerender when the value changes. Exposure **must** be offered solely as a processing adjustment.
- User-facing stage names **must** be unqualified until alternative implementations require a distinction. The noise/detail stage **must** use a single **Noise and Detail** checkbox as both section header and enable toggle, with its controls underneath and the advanced subsection labeled **Advanced**. Section labels **must** use title case, including **Tone and Color**. “Reconstruction” **must** remain an internal term rather than a separate editing label. Technical attribution remains in implementation guidance.
- ColorDQ gain **must** appear first in **Noise and Detail → Advanced**, above the linked parameters. It **must** stay hidden when that subsection is collapsed or Noise and Detail is disabled, without an inactive warning elsewhere. It **must** use an **A** toggle immediately left of the value input. Automatic mode **must** keep the row visible within the open subsection and disable the slider and value editing. Resolved automatic values **should** be shown when available. Otherwise the value field **may** show `Auto`.
- Editing **must** group Sharpen under **Refinement**, followed by **Corrections** with **Highlights** first and **Speckles**, **Bad pixels**, and **Row banding** under a collapsed-by-default **Advanced** disclosure. Those three corrections **must** default on for new edits and preserve saved choices. The two Advanced disclosures **must** open independently without changing processing settings. Correction controls **must** use inline enable checkboxes. Highlights' threshold slider and **A** button follow [highlight restoration](./highlight-restoration.md); its help and widget identity **must** remain distinct from tone Highlights.
- Bad pixels **must** use camera-derived cutoff selection internally, without a cutoff slider, value field, or **A** toggle. Bad pixels and Speckles **must** remain independently switchable and enabled by default. Help **must** distinguish repair of camera-recorded pixels/clusters and targeted red-pixel detection from Speckles' image-based search for isolated dots. The manual CLI cutoff override remains available for diagnostics.
- Aperture **must** display an integer or one decimal place, such as `f/4` or `f/2.8`. Shutter **must** display a photographic fraction or seconds. Prefer recorded display labels when available.
- Metadata **must** include available camera, lens, focal length, aperture, shutter, ISO, exposure compensation, exposure program, metering, white balance, dimensions, capture date, software, serial, color mode, and color space. Show only fields available in the file.
- A compact information bar **must** sit below the main image viewport, showing photographic metadata, filename, and visible-region dimensions and coordinates. Its layout and remaining coordinate questions follow [image information bar](./image-information-bar.md).
- UI preferences **must** survive application restarts using platform-appropriate application storage. Persist pane/window geometry, organizer mode, section order/collapse state, selected scope, and zoom snap target as their controls are implemented. Keep the application identity stable.
- UI settings **must** save the last successfully opened organizer folder and reopen it on application startup. An explicit launch path **must** take precedence. Opening a file remembers its containing folder; unavailable saved folders **must** report the error without opening a different folder or blocking use of the app.
- Photographic-settings persistence **must** follow [editing sidecars](./editing-sidecars.md). UI-preference storage **must** remain limited to workspace choices and geometry.

## Implementation direction

Editing, inspection, and scope explanations follow [photographic control help](./photographic-help.md).

Use eframe's built-in persistence with app ID `foveonic`. Store explicit UI preferences separately from processing `Settings`; eframe/egui handle window and widget layout memory. Missing or unreadable preferences use defaults. Native smoke tests use isolated storage.

Scopes sample a grid of at most 512×512 from the displayed GPU buffer, keeping the region's aspect ratio without upscaling. Only counts and weights are read back. Whole-image and viewport scopes share one background worker path. Image processing takes priority. Replies must match the displayed image revision and requested region.

Waveform/parade use bilinear placement with 256 weight units per sample. Splitting keeps each sample's total weight unchanged. Display converts weights to sample units before logarithmic brightness mapping. Display images are Lanczos-resized to the plot's physical pixel size and drawn one-to-one. Cache them until content or size changes. Resize parade channels separately so their colors do not mix.

RGB keeps its working primaries and linear transfer state. The combined RGB waveform includes matching sRGB or Adobe RGB luminance. Sensor/calibrated layers and pre-tone RGB use 0–4095, scalar fields use 0–1, luminance ratios use 0–2, and signed detail uses −1000…1000 camera codes. Scopes use all buffer channels regardless of display selection. Inspection offers image buffers; node-data diagnostics are deferred.

The owner's Capture One screenshots guide the three-pane arrangement. The local `x3fuse-multiplat` checkout at `7ddebcd` provides visual and behavioral references for navigator, scopes, metadata, and dark neutral styling. Its current branch is `feature/tauri-dng-looks`. These references inform layout and interaction.

## Conformance

Icon and bundle tests cover light/dark specialization references, preserved RGB layers/geometry, disabled glass, compiler metadata, executable permissions, and input-path forwarding. Native macOS 26 checks confirm Aqua/DarkAqua compiled icon stacks, native bundle-icon recognition, release/debug builds, and both direct bundled and LaunchServices smoke launches. Visual system-icon-style review remains in the [icon plan](../../plans/icon-background.md).

Viewport scope tests and owner acceptance are recorded in the [viewport scopes plan](../../plans/viewport-scopes.md).

Unit and GPU fixtures cover organizer reflow, pointer-driven section collapse/reordering, pane-local drop limits, navigator click/drag/double-click geometry, slider rerender signals, slider reset/numeric entry, focused nudging/bounds/parameter overrides, metadata formatting, preference restoration, and oriented signed/scalar/sensor/RGB scope values. Native macOS checks capture the workspace and all scope modes on six originals; a second isolated launch verified organizer, section, and scope restoration before sidecars were implemented. Photographic settings now restore through [editing sidecars](./editing-sidecars.md), independently of those workspace preferences. Owner interaction review and cross-platform runtime checks remain in the [implementation plan](../../plans/gui-and-batch.md). Last-folder persistence/launch precedence and visible pixel bounds have unit checks. Six-image native captures and a no-path isolated restart verify the information bar and folder restoration in the [editor review plan](../../plans/editor-review-focus.md).
