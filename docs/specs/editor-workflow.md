# Editor workflow controls

On-image eyedroppers must be one-shot. A patch or range click must disarm its picker on pointer release while allowing its pending result to finish safely. Direct color editing must disarm when its click or drag ends, including when selection is still pending. Ordinary image navigation must resume without a second toolbar click. Starting another tool or changing the photo or recipe must still reject obsolete results.

Each editing section must offer a reset arrow and a preset menu. Tone, Saturation and Color Range have independent scopes, including their methods, amounts and enable switches. Ordinary reset restores that section from the user's configured defaults. Option/Alt-click restores its camera-as-shot baseline instead. Matching controls at the top of Editing apply to the whole photographic recipe. Section actions must leave other sections and workspace state unchanged.

Editing and browser popup menus must use adjacent rows with shared font-based padding. Separate meaningful groups once, without empty groups or consecutive separators. Menus must size to their longest label plus shared padding. Shared row measurement must ignore provisional popup width during sizing passes, then fill the measured width when displayed. Dropdown labels and menu rows must use the same intrinsic text measurement. Open dropdowns must account for their own frame padding so ordinary options stay within the closed control’s width. Exclusive choice groups must remain in the same popup, with a non-selectable heading aligned to ordinary items and only their options indented. Choosing an option, clicking outside or pressing Escape dismisses the menu. Clicking a heading must not select anything or dismiss it.

Button groups must use the same shared padding, including Basic/Advanced choices inside a section header. All editing headers reserve the padded group height and center their titles and compact actions. Automatic A buttons use the shared square control geometry, and numeric rows reserve that same measured width.

Editing subsection titles, including Noise, must use one shared style slightly larger than parameter labels, with softened white text in the dark theme and strong foreground text in the light theme. Reset and preset glyphs should be compact within their existing click targets. Reset uses a left-pointing undo arrow with a rounded return inside a bordered button. Editing-tool drag grips should match the larger workspace grip for visibility.

Editing rows must use a shared pane-relative label column, initially one quarter of the available row width. Sliders and dropdowns fill the remainder. Only a displayed label that cannot fit may take additional space and temporarily shorten its control. Expanding the pane must restore the shared alignment. Expanded disclosures retain their label indentation while controls stay aligned to the parent column when their labels fit. White Balance, Tone, Saturation, Color Range and Noise use this shared layout. Both method selectors display Method. Tone displays its existing local-contrast control as Clarity. Noise labels its neutralization amount Neutralize and its options disclosure Neutral Range. All four neutralization sliders and the Neutral Range disclosure must share one visible parameter group. Integer and decimal value boxes share a standard minimum width so ordinary numeric formats do not change slider lengths. Wider values remain readable. Automatic controls retain space for their A button. Controls within a visible group must share left alignment. Indentation belongs to expandable disclosure groups. Detail size, highlight thresholds, speckles and banding must not add another indentation level inside their visible groups.

Draggable workspace sections must leave horizontal breathing room around their contents. Parameter group backgrounds must extend outward to provide matching horizontal and vertical breathing room without moving their controls. Disclosure lines must align with the parent label edge while their child controls retain indentation. Editing dropdowns must fill their row to the same right edge as numeric value fields in that container, truncating long selected labels rather than widening the pane.

Reference banding must distinguish Column strength from its separate automatic Correct row offsets switch. Help must explain that these axes follow sensor coordinates and can appear rotated in the photograph. Directional banding's Fine and Coarse parameter pairs must use a slightly lighter background than their enclosing Banding group.

Preset menus must support naming, saving, applying and deleting custom presets. Presets and user defaults live in application storage, separate from photo sidecars. Section presets store the same photographic schema as whole-recipe presets but apply only their declared scope. Preview quality, viewport, output dimensions, TIFF destination space, processing masks, browser ratings and panel arrangement must not be transferred. User defaults are retained per camera architecture. Saved photo edits take precedence. Setting defaults must not rewrite existing photographs.

White Balance must offer As Shot alongside available camera presets, with neutral-centered Warmth and Tint adjustments anchored to the selected balance. As Shot follows each file rather than copying another photograph's resolved preset. A zero bias must preserve the existing rendering. White balance must remain coherent between display, TIFF and DNG. DNG neutral/profile composition must apply the adjustment once and retain normal downstream WB adjustment. Temperature readouts must not imply an exact recorded Kelvin value when only gains are available.

Warmth and Tint use the same linear cone-response adjustment in every color pipeline, before Color Editor and shared photographic edits. Sensor monochrome retains those offsets as inactive values. Its camera WB selector follows the existing family capability. Pure WB bias does not alter technical DNG samples. Its neutral and profile carry the selected interpretation. Previously baked WB-dependent reconstruction remains baked.

Y toggles the requested edit against a camera-as-shot rendition. Shift+Y compares against the user's default recipe. The comparison must use the same RAW pipeline and image geometry, preserve zoom/pan, and display a Before badge at the upper left of the viewport. Comparison is transient. It must not change authored settings, sidecars, processing submissions, navigator/browser photographic preview recipes or preset contents. Text inputs and open menus retain their keyboard exclusions. Editing returns to the requested edit view.

The camera-as-shot baseline resolves the file's recorded WB, color mode and capture-dependent photographic defaults through the existing camera adapter. It is a RAW rendition rather than the embedded JPEG. User defaults overlay that baseline while respecting camera capabilities. Unsupported controls must be normalized without changing the saved preset or default template.

## Verification

Automated checks cover scoped copying, independent Noise/Detail resets, preset replacement and persistence, family defaults, preview invalidation, reset modifiers and shortcut routing. Original-file GPU checks cover shared WB and chromatic DNG reprojection on Classic, Merrill, Quattro and Quattro H. Native checks exercise camera/default comparisons, unchanged authored recipes, retained viewport coordinates, reuse of the current GPU image and exclusion of Before frames from photographic preview publication.

Corrections must have an enable checkbox across camera families. Bypass disables its controls and optional Dehaze, highlight restoration and bad-pixel corrections while retaining their saved values. It must stop automatic Dehaze estimation and pending picker edits. Merrill Noise-owned speckles and mandatory camera calibration remain in their own scopes. Corrections presets/defaults/reset include its enable state.
