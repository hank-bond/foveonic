# Processing reference fixtures

Most fixtures were generated with the reference implementation's diagnostic library from an audited source snapshot based on `e47af35`. The monochrome fixture uses the standalone adapter described below.

- `noise-reference.json` records component outputs for a deterministic 80×72 synthetic signal and a separate 2×2 tile-blending case. [The component test](../../src/nodes/color/reconstruction_test.rs) defines the input, parameters, sample locations, and arithmetic tolerances. Reference functions are `filter_tables`, `radius_map`, `bilateral`, `edge_map`, `edge_lut`, `local_mean`, `brightness`, `noise_diffusion`, `diffusion`, `osf`, `ratio`, `color_mixing`, `foveonic_reconstruction_signal`, `apply_color`, and `foveonic_blend_tiles`.
- `noise-parameters.json` records `foveonic_processing_params_source` results for the six original Merrill photographs, using Sunlight WB and each file's aperture/shutter properties. [The parameter test](../../src/nodes/color/noise_test.rs) checks the selected tables, histogram-derived ISO, WB-weighted model, and calibration scaling.

- `repair-reference.json` records the blue sign's two unlisted red-speckle positions, original sensor samples, and reference `foveonic_calibration_source`, `foveonic_repaired_source`, `foveonic_restored_source`, and `foveonic_despeckled_source` results. Sunlight WB, aperture 3.2, one exposure, and exposure gain 1 were used. Regular repair and highlight restoration leave both centers unchanged; despeckling emits red-layer records (`0x43ff`) and corrects them. [The record-selection test](../../src/nodes/sensor/repair.rs) checks that current camera-list selection leaves these source positions unmarked at cutoffs 0–3. The implemented separate GPU despeckle stage now corrects both centers.

- `ordered-repair-reference.json` retains a 24×20 signed/headroom synthetic source, all repaired samples, and reversed-order output from `foveonic_bad_pixels` with no override masks. It covers all seven layer combinations, partial masks, duplicate/adjacent records, cutoff selection, asymmetric borders, genuine-zero extrema sentinels, and unknown layer flags. [Ordered repair tests](../../src/nodes/sensor/repair_test.rs) compare every output sample at gains 0/1/1.3 and regress the photographic 2×2 leaf defect with independent retained artifacts.

- `complete-camera-reference.json` retains immutable raw samples, distinct calibrated samples, main/JPEG records, unscaled noise-model values, packed clusters, detected records, main overrides, and the complete native output. It covers detection before calibration/gain, low-badness detector inputs, duplicate records/detections, list order, overlapping mixed-layer clusters, stable quality sorting, and exact cluster-class selection. [Complete camera tests](../../src/nodes/sensor/camera_repair_test.rs) compare every output sample and runtime record at gains 0/1/1.3; a separate test covers capacity-minus-one and exhausted override masks.
- `dark-defect-reference.json` retains the reported flower-background defect at image `(1155,804)`, a 9×9 calibrated input, eleven JPEG repair records, and native ordered JPEG output. The full photographic regression also checks the subsequent overlapping packed-cluster repair, independently of despeckle.

- `despeckle-reference.json` retains a 64×64 synthetic source, all corrected samples, ordered records, and selected metadata-threshold entries from `foveonic_detect_speckle_band`, `foveonic_bad_pixels`, and `foveonic_speckle_tables`. Zero detector adjustment exposes peaks/valleys, all seven layer combinations, adjacent mixed-layer detections, native margins, and headroom clamping. Lookup samples separately use gains `[2.3,1.1,0.8]` and adjustment `[15,15,5]`. [GPU regression checks](../../src/nodes/sensor/despeckle_test.rs) compare every output sample, immutable input, and bounded record order.

- `highlight-reference.json` retains calibrated samples, original and connected per-layer flags, 5×5 clipping-neighborhood density, and native `foveonic_restore_highlights` output. [Highlight tests](../../src/nodes/sensor/highlight_test.rs) cover original flags independent of processed clipping, isolated flags, ordered blue/green donor correction, brightness neutralization, preserved borders, and immutable ownership. A photographic density-only test checks metadata-only selective execution without WB/color/repair setup.

- `banding-reference.json` retains native SVD matrix samples and complete row-offset sums/counts for a deterministic 1600×640 source reconstructed by [banding tests](../../src/nodes/sensor/banding_test.rs). It covers all three patch sizes and all eight banks, transposed fits, stable row contributions, native bounds, WB discard limits, and immutable inputs. Reference entry points are `foveonic_banding_matrices` and `foveonic_banding_patch_bank`.

- `column-reference.json` retains native color-column output for an 80×112 striped/signed/headroom source, two ordered 40-row blocks with a final extended block, strict correction eligibility, and asymmetric filter/correction margins. [Reconstruction tests](../../src/nodes/color/reconstruction_test.rs) check gain 0/1/1.3 and unchanged input. Native `column` uses a 32-byte vtable/data/width/height/stride/padding header; the source extra row and square scratch clear have safe backing.

- `pattern-reference.json` captures native grouped min/max masks, edge-seeded scratch with LocalMean margin 8, deterministic offset sequence, and ratio conditioning at blends 0/0.65/1. [Pattern tests](../../src/nodes/color/pattern_test.rs) cover wrap order, two independent tiles, negative/zero ratios and immutable inputs. `pattern-parameters.json` records native pattern thresholds/blend/half-size for six originals × five chroma choices, checked by [noise preparation tests](../../src/nodes/color/noise_test.rs).

- `sharpen-reference.json` captures native mono high-pass and final color sharpening with signed/zero/HDR RGB, quarter-code packing boundaries and negative wrap, native ceilings/limits, and amounts 0/0.75/2. [Control shader tests](../../src/controls_test.rs) replace the former Gaussian convolution fixture and check unchanged inputs.

- `resample-reference.json` captures exact native polyphase metadata and RGB down/restore output for scales 0.375/0.5/0.625/0.75/0.875/1. [Resampler tests](../../src/nodes/finish/resample_test.rs) check two tile resets, scalar output, unchanged inputs, and zero bottom rows.
- `reduced-reference.json` captures global fixed/margin-4 filtering and local 0.75 down/base/restore/F backing. [Reconstruction tests](../../src/nodes/color/reconstruction_test.rs) check native borders, restored geometry, and explicit transposed seeds.
- `recipe-parameters.json` captures scale, fixed window, despeckle scale and ColorDQ limit for six originals × five coupled chroma/luminance choices. [Noise tests](../../src/nodes/color/noise_test.rs) verify scale/window and correction recipe couplings.

- `monochrome-reference.json` retains the complete 48×48 monochrome input and directional, column, histogram, despeckle, and signed quarter-code outputs. A standalone adapter compiled the read-only reference implementation's `monochrome_bilateral.rs`, `monochrome_despeckle.rs`, and `monochrome_detail.rs` and called their ordinary finite full-scale functions. The fixture retains directional window 15, directional divisor 0.375, histogram divisor Float32 0.3, column level 2, ISO 100, and processing gain 2. Input includes sharp outliers. A double-width zero-padded input backs the reference diagnostic contracts. [Mono component tests](../../src/nodes/monochrome/tests.rs) compare all outputs. Independently initialized GPU column histograms differ slightly in Float32 traversal history. The fixture does not establish exceptional fallback or primary-mono calibration behavior.

GPU arithmetic uses float32. Component checks allow small numerical differences in camera-code values; overlap projection matches the reference fixture exactly. Noise JSON includes selected interior samples; repair/despeckle fixtures retain complete small-image outputs. Preserved-border checks, full-sensor reference replay, and full-image finite-value checks complement them.
