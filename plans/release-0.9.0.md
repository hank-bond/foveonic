# Release 0.9.0

The owner authorizes merging the completed wide-rendering work into main, preparing the next minor release and running the new release test process. The subsequent Shift viewing reports belong to this candidate: each photograph must preserve its own point at the same relative position within its displayed region, independently of aspect ratio or pan. Shift-drag must move every edited photograph by the same on-screen displacement. Publication remains a separate owner review.

Requirements: [release specification](../docs/specs/releases.md), [release guide](../docs/releases.md), [test inventory](../docs/testing-coverage.md) and [multi-edit viewing](../docs/specs/multi-edit.md#per-photo-viewing). The release build enables the previously explicit wide feature. Preserve subsequent main changes through 0.8.4, including capture metadata, encoder compatibility, Windows startup and the new test process.

The Shift-zoom fix passes all 639 ordinary GUI checks after reproducing both the visible mixed-aspect bug and a known-hidden Fit regression. The Shift-pan case independently reproduces unequal on-screen displacement before its fix. The final combined GUI suite passes all 642 ordinary tests, including mixed aspect ratios, both source orders, different zooms, display densities, Space/tool isolation and hidden/carry behavior. Independent reviews have no outstanding findings. These intermediate checks do not replace the final candidate run.

The release process uses one frozen source/configuration, independent Mac and Windows lanes, maintained required-test classification, bounded concurrent slider sessions with independent numerical verification, exact packaged startup/rendering checks and separate exclusive performance. Published 0.8.4 is the performance baseline. A conditional parallel-host schedule is not a release duration guarantee.

## Packaged performance review

Published 0.8.4 and the exact signed draft ran on the same quiet 32 GiB M1 Pro Mac, using matched inputs, delivered grids and cache settings. Twenty-one of 22 latency observations were comparable, including reversed runs. The eight-photo pressure comparison remains unavailable because one of the three 0.8.4 trials started with a different grid. All candidate catalog trials completed. All seven memory workloads have three matched pairs sampled separately from latency.

Eight-photo warm edits repeatedly took about 29 to 33 ms longer to report group readiness. At 6 GiB their median was 218 to 250 ms. These timings include the embedded progress readiness boundary and do not isolate rendering cost. The warm-disk selection difference changed direction when run order reversed. Single-photo warm edits, cached switching, HDR and ColorField warm edits were broadly flat. In reversed native-detail runs, foreground zoom was about 484 to 483 ms for one photo and 849 to 833 ms for two. Optional whole-image completion was about 283 and 584 ms later, respectively. At 6 GiB, the two-photo foreground stayed near 816 ms while whole-image completion was about 617 ms later.

At a 2 GiB cache budget the median sampled peak fell in all five matched workflows, including about 31 MiB for mixed eight-photo editing and 184 MiB for two-photo native detail. At 6 GiB the median sampled peak grew by about 95 MiB for mixed eight-photo editing and 239 MiB for two-photo native detail. Samples are spaced about 100 ms apart and can miss true peaks. Sustained idle settlement, GPU residency, cold startup, physical presentation, six-photo native detail and Windows performance remain unmeasured. Review the repeated group readiness change, larger-budget memory growth and unavailable pressure comparison before publication.
