# Memory sweep

Requirements: [photographic output](../docs/specs/output-strategies.md) and [performance diagnostics](../docs/specs/performance-diagnostics.md).

The owner requested an autonomous sweep, prioritizing peak memory and simpler designs. Preserve export samples and editing behavior. Keep retained-resource estimates separate from measured process or GPU peaks.

- [x] Repack JPEG and RGB8 PNG directly from packed GPU output. This avoids a six-byte-per-pixel RGB16 allocation, approximately 92 MiB at 4928 × 3264. Exhaustive RGB8 PNG quantization and existing encoder tests pass. This is an allocation calculation, not a measured process peak.
- [x] Shorten Color Field solver buffer ownership. Native equations consume 48 bytes per active native pixel and coarse equations and solutions consume 96 bytes per active grid cell. The buffers can be released after their last submitted consumer. Three alternating full-photo Local JPEG exports per variant produced identical files. RSS was 697 MiB without early release and 696–698 MiB with it. Footprint was 1476–1484 MiB without release and 1468–1489 MiB with it. This photograph showed no clear process-peak gain. The active-pixel count and driver residency determine the effect in other scenes.
- [x] Release the speculative decoded source before publishing selection assets. This shortens its overlap with publication. A native Merrill source holds approximately 184 MiB of sample data. The earlier decode peak is unchanged. The portable cache tests pass. Original-file prefetch tests require declared fixtures.
- [x] Rejected mapped export readback after testing. It removed an eight-byte-per-pixel host copy but kept staging alive through encoding. Three release JPEG exports of each variant, alternated, of the example blue photograph produced identical files and showed no clear peak benefit over the same candidate without mapped readback: RSS 774–777 MiB versus 774–781 MiB, physical footprint 1728–1732 MiB versus 1730–1734 MiB. The mapped implementation was removed. These observations cover one image and one format, not every workload.
- [x] Rejected color texture plane reuse after testing. It reduced scalar allocation requests from nine to three but did not reduce process peak in three alternating full-size JPEG exports per variant with active Fine/Coarse controls. RSS was 779–780 MiB without reuse and 780–785 MiB with reuse. Physical footprint was 2873–2874 MiB without reuse and 2874–2875 MiB with reuse. Files were byte-identical. The change was removed. These results cover one image and recipe.
- [x] Rejected monochrome texture plane reuse after testing. Three alternating fresh full-photo renders per variant with active Fine/Coarse controls showed RSS of 779–783 MiB without reuse and 778–780 MiB with reuse. Physical footprint was 2150–2213 MiB without reuse and 2148–2150 MiB with reuse. The earlier path had one higher-footprint outlier. The cached/fresh and DNG boundary check passed, but the peak benefit was not clear enough to retain the extra reuse machinery.
- [x] Release GUI preview source samples after linearization and unrotated floats after rotation. This shortens overlap by 6 bytes per input pixel, plus 12 for rotated previews. GUI rotation and resize tests pass.
- [x] Widen ICC preview input in bounded chunks instead of a full RGB16 copy, avoiding 6 bytes per preview pixel. Preview tests and an exact multi-chunk comparison pass.
- [x] Stream JPEG XL output through a 64 KiB buffer rather than retain the complete encoded file. Lossless multi-chunk round trip, writer failure and existing encoder tests pass.
- [x] Release RGB16 preview samples before floating resize. Review caught an initial extended float lifetime. An inner scope fixes it. Preview tests pass.
- [x] Prepare rendered display previews from their linearized samples without cloning the RGB16 payload needed for persistence. GUI preview tests pass.
- [x] Stream uncompressed TIFF repacking one encoder strip at a time. Exact multi-strip output and existing compression/profile tests pass. Three alternating native example exports per variant gave byte-identical TIFFs. RSS fell from 846–848 MiB to 782–785 MiB while peak footprint overlapped at 1736–1739 MiB versus 1734–1740 MiB. Compressed TIFF retains the existing whole-image path because the encoder enables compression only through its whole-image API.
- [x] Stream RGB16 PNG output by row, avoiding full-image RGB16 and endian-reordered buffers. Three alternating native example exports per variant reduced RSS from 901–940 MiB to 778–785 MiB. Peak physical footprint overlapped at 1729–1739 MiB versus 1736–1740 MiB. Decoded full-resolution RGB16 samples and ICC profiles matched. Chunking changed compressed bytes and increased the measured file from 81,974,414 to 82,214,589 bytes. Multirow and injected writer-error tests pass.
- [x] Retain unsigned format-30 sensor codes as 16-bit samples in memory and widen directly into the GPU upload buffer. Existing signed and synthetic float sources remain floating. Warm decoded-cache entries keep unsigned Merrill samples compact without changing their disk format. The public `Source::samples()` returns a borrowed or owned `Cow` and allocates a full float copy when called for compact sources. Production upload and cache paths avoid that conversion.
- [x] Retain the three original decoded Merrill planes and interleave while uploading or writing cache chunks. Five alternating example `inspect` runs reduced peak RSS from 252 MiB to 160 MiB and footprint from 247 MiB to 154 MiB. Three TIFF export runs reduced RSS from 687–688 MiB to 597–604 MiB and footprint from 1602–1646 MiB to 1517–1559 MiB. The TIFF files matched byte-for-byte. Warm elapsed times were comparable in these limited runs.
- [x] Rejected PNG8 row streaming after three alternating example exports. It removed a full RGB8 buffer, but RSS and physical-footprint ranges overlapped and the runs were slightly slower. The output size grew from 32,302,628 to 32,397,279 bytes. The change was removed.
- [x] Rejected Classic highlight scratch reuse and earlier drops after five alternating full-size example exports. Output files were byte-identical, but RSS and physical-footprint ranges overlapped. The change removed one full scalar allocation request without changing observed process peak in this workload, so it was removed.
- [x] Rejected a DNG buffer-lifetime change after five alternating full-size example exports. Files were byte-identical and GPU encoding tests passed, but RSS and physical-footprint ranges overlapped. The change was removed.
- [x] Recompute the DNG camera transform during quantization instead of retaining a full RGB32F camera buffer. Five alternating isolated 4096 × 3072 dense-matrix encoding runs lowered peak physical footprint from 879–948 MiB to 735–785 MiB, with matching encoded samples. End-to-end example DNG export peaks overlapped because other stages dominated. Resized 1234 × 987 DNG exports using Auto/Standard were byte-identical for `sd1-merrill-full.x3f`, `sd1-merrill-low.x3f`, `dp3-merrill-low.x3f` and `dp3-merrill-medium.x3f`.
- [x] Reuse the smoothed reconstruction workspace for column-conditioned tiles after its last read. In a full-size example `--reconstruction` profile, processing requested 246,497,280 fewer storage bytes and one fewer allocation; dispatch and submission counts were unchanged. Five alternating TIFF exports per variant produced identical files, while process RSS and physical-footprint peaks overlapped. This demonstrates reduced allocation traffic, not a measured process-peak reduction. The column preset test now preserves its configured block height, and all eight ignored reconstruction tests pass across the original run and the corrected preset rerun.
- [x] Reuse raw reconstruction tiles for directional prefix sums after bilateral filtering. Full-size `--reconstruction` profiles requested one fewer allocation and 138,654,720 fewer storage bytes for the blue example (0.75 local reduction), and 27,143,424 fewer bytes for `rocks-and-tree-shadows.x3f` (0.375 global reduction; SHA-256 `2cce73035afea1dd180b4215095f36e400183104ba8d296734d265b8e42a65ef`). Three alternating TIFF exports per variant for each image were byte-identical. RSS and physical-footprint ranges overlapped; blue baseline footprint varied between runs. The eight ignored reconstruction tests pass, including local and global numerical fixtures.

## Release export observations

On this Apple Silicon macOS host, release builds compared main `fa4a09c` with the code later committed as `21d7d8f`, using the example release's `blue-parking-sign.x3f` (SHA-256 `7a650537a9986bfe348e0da117defbf80da7ceca35f76bc092f220a7cdbcffee`), Sunlight/Standard and default processing. Three fresh CLI processes per variant alternated, with `/usr/bin/time -l` reporting maximum RSS and peak memory footprint. The same output bytes were produced for every matched run. The later texture-reuse reversions do not affect these neutral-detail exports. These are process-level observations for one export workload, not native GUI or retained-session measurements. Process startup and filesystem cache were uncontrolled, and timing is not used as acceptance evidence.

- JPEG: main RSS 807–845 MiB, candidate 774–781 MiB. Main footprint 1731–1735 MiB, candidate 1730–1734 MiB.
- Lossless JPEG XL, effort 1: main RSS 1138–1145 MiB, candidate 900–1011 MiB. Main footprint 1731–1738 MiB, candidate 1731–1734 MiB. All outputs were 85,427,843 bytes and byte-identical.

The first JPEG comparison overlapped a separate build and is excluded. Physical footprint did not show a material improvement in these runs despite reduced RSS and allocation traffic. The initial workspace test run overflowed a GUI test thread's default stack. The complete workspace passed with `RUST_MIN_STACK=8388608`. Strict Clippy, formatting, documentation index and Python checks also passed before the mapped-readback removal.

## Remaining investigation

Merrill decoding retains its three original planes. An earlier serial plane prototype was discarded because it bypassed shared decode pool admission and priority rules, changed diagnostic boundaries, and forfeited parallel decoding. Any future streaming design must preserve those requirements and demonstrate an acceptable loading tradeoff. Within-node GPU scratch and native multi-photo application memory also need representative measurements.

## Compact source observations

On the same example blue photograph, five alternating fresh `inspect` processes compared the pre-change release build with compact sources. Peak RSS fell from 344 MiB to 252 MiB and peak physical footprint from 339 MiB to 247 MiB. The first compact run took 1.06 seconds. The remaining runs took 0.57–0.59 seconds versus 0.59–0.61 seconds before. Filesystem cache and process startup were uncontrolled, so these are not latency acceptance thresholds.

A cache written by the prior implementation was loaded in five alternating fresh processes using an isolated diagnostic cache namespace. Retained source accounting fell from 194,658,001 to 98,148,057 bytes. Peak RSS fell from 201 MiB to 109 MiB and physical footprint from 196 MiB to 104 MiB. Three alternating uncompressed TIFF exports per variant produced identical bytes. RSS fell from 776–783 MiB to 690–694 MiB and footprint from 1692–1737 MiB to 1606–1648 MiB.

Canonical little-endian float-bit SHA-256 hashes of all original source samples matched main `fa4a09c` for the example blue photograph and the four declared SD1/DP3 HI, MED and LOW originals. The check opens each original through `Source::open`, visits samples in storage order, converts each float bit pattern to four little-endian bytes and hashes that byte stream. Color and monochrome TIFF outputs were also byte-identical for the four SD1/DP3 originals. Canonical source hashes also matched for one Classic SD9 and one DP2 Quattro original. The generated LOW cache test checks direct compact read/write, a chunk tail, exact retained-capacity accounting and corruption rejection. A GPU test checks every unsigned 16-bit value across an upload chunk boundary. Another checks cancellation before allocation. Cancellation after mapping is reviewed but not directly tested. The real-file cache selection test passed.

The existing full/medium/low Merrill rendering test failed its reduced monochrome extent assertion on both this branch and unmodified main. That failure was not retried into a pass or weakened. The workspace suite passed with the larger test-thread stack. All-target Clippy passed after replacing a fixed-size chunk iterator as requested by the current lint.

The original-file sample checks used these source and canonical-sample SHA-256 pairs. The input names and acquisition requirements are in the [X3F specification](../docs/specs/x3f-input.md), with the DP3 files also listed in the tracked profiling input manifest. ## DNG encoding observation

The isolated encoding fixture uses a generated 4096 × 3072 RGB frame whose sample `i` is `(i × 37 mod 10001) × 0.5 - 300`. It uses the dense matrix and neutral values in the DNG GPU test. The prior implementation at `e7c5b7b` and the recomputing implementation produced identical packed-sample SHA-256 `7c866a84dc8a920190382842707b59ed5433b3da6ff9bc8c7a868676cd33fd38` and scale bits `4024a838` on the Apple M1 Pro. The fixture loads the declared example blue photograph only for camera metadata. These observations are specific to this adapter and stage-level workload. The maintained test independently checks each generated encoded sample against scalar arithmetic within one code, rather than requiring one device's float hash on every adapter.
